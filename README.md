# מילה. — כולנו מבטיחות. בואי נראה מי מקיימת.

משחק חברתי של התמדה: כל אחת בוחרת עד 3 אתגרים מספרייה של 50 (או אתגר משלה) ל-14 יום, מדווחת כל יום, והקבוצה מתחרה על אחוז ההתמדה.
כל הצלחה = נקודה; פספוס מאפס את הרצף של אותו אתגר ולא מוריד נקודות. הדירוג לפי אחוז התמדה, ובסוף 14 יום יש מנצחת. בלי כסף, בלי תשלום, בלי קופה.

(מבנה הנתונים שומר על יומן append-only עם סוגי תנועה EARN / MISS_TO_CIRCLE / MISS_PERSONAL / REVERSE. בממשק EARN = נקודה, ושאר הסוגים = פספוס. אין יותר ״שקלים״ ו״קופה״ בשום מסך.)

PWA בעברית (RTL) על תשתית חינמית: **Cloudflare Workers + Static Assets + D1**, התחברות עם **Google**.
אין שירות בתשלום, אין אמצעי תשלום, אין תלות ב-CDN חיצוני.

## פריסה (Cloudflare Free)

הגדרה חד-פעמית בחשבון Cloudflare (ללא אמצעי תשלום):

```bash
npx wrangler login                                   # או CLOUDFLARE_API_TOKEN
npx wrangler d1 create mila-db                       # staging  → להעתיק את database_id ל-wrangler.toml
npx wrangler d1 create mila-db-prod                  # production → להעתיק ל-[env.production]
npm run db:migrate                                   # מיגרציה ל-staging
npm run db:migrate:prod                              # מיגרציה לייצור
npx wrangler secret put GOOGLE_CLIENT_SECRET         # staging
npx wrangler secret put GOOGLE_CLIENT_SECRET --env production
npm run deploy                                       # https://mila-staging.<subdomain>.workers.dev
npm run deploy:prod                                  # https://mila.<subdomain>.workers.dev
```

לפני פריסה לייצור בפעם הראשונה אחרי 2.0: `npm run db:migrate:prod` (מיגרציה 0002).

ב-`wrangler.toml` ממלאים את `GOOGLE_CLIENT_ID` (ציבורי) לכל סביבה. ב-Google Cloud Console → OAuth client (Web):
Authorized redirect URIs = `https://<host>/api/auth/google/callback` לכל סביבה.

סביבת הבדיקות (`mila-staging`) מאפשרת `POST /api/auth/test-login` לבדיקות אוטומטיות; בייצור הנתיב מוחזר כ-404.

## עומס, מכסות וגיבוי

נמדד בבדיקת עומס על staging (`npm run test:load`, 24 משתמשות במקביל, קבוצות של 6, 3 אתגרים לכל אחת). אין שגיאות; p95 מתחת לשנייה.

| פעולה | שורות D1 נקראות לבקשה |
|---|---|
| טעינת מצב מלאה (`GET /api/state`) | ~380 |
| בדיקת ״יש חדש?״ (`GET /api/ping`, כל 45 שנ׳ כשהמסך גלוי) | ~6 |
| דיווח | ~25 |

מה שעושה את זה זול:
- הדירוג ו״המהפך״ מחושבים בטלפון (שכבר מחזיק את הנתונים); השרת רק רושם עקיפה (`action/overtake`).
- ריענון אוטומטי = `ping` זול; מצב מלא רק כשיש חדש או אחת ל-10 דקות.
- מצב קל: ימים של חברות רק עד היום, היסטוריה 30 יום (שלי 90), אירועים 21 יום, 40 התראות, יומן נקודות אישי בלבד.
- ״נראתה לאחרונה״ נכתב לכל היותר פעם ב-10 דקות; פעילות יומית = שורה אחת ליום (`user_days`).
- קבצי האפליקציה עם גרסה (`?v=`) נשמרים במטמון הדפדפן וה-Service Worker לשנה ולא נשלחת בקשה בכל פתיחה.

הערכה למסלול החינמי (מודל: 5 טעינות מלאות, 10 בדיקות קלות, 3 דיווחים ליום): **כ-2,000 משתמשות פעילות ביום**. צוואר הבקבוק: כתיבות D1 (100K ליום) וקריאות D1 (5M ליום). כשמגיעים למכסה Cloudflare מחזירה שגיאה (לא חיוב), האפליקציה מציגה ״הגענו למכסת השימוש היומית״, והמכסה מתאפסת בחצות UTC. **הנתונים לא נמחקים.** מעבר לזה צריך Workers Paid (החלטה בתשלום, לא מופעלת).

גיבוי:
- **Time Travel** של D1 פעיל: שחזור לכל דקה ב-7 הימים האחרונים. `npx wrangler d1 time-travel info mila-db-prod --env production`.
- ייצוא מלא: `npm run backup:prod` (קובץ `backup-prod.sql`, לא נכנס ל-git).

## פאנל ניהול

הגדרות ← ״פאנל ניהול״ (רק למנהלת המערכת). המנהלת מזוהה בכניסה לפי `ADMIN_EMAIL_SHA256` ב-`wrangler.toml` (גיבוב של האימייל, לא האימייל עצמו). מציג: משתמשות (רשומות, פעילות יום/שבוע/חודש, חדשות, חזרו אחרי שבוע), הזמנות (נשלחו ← פתחו ← נרשמו ← הצטרפו) והמזמינות המובילות (כמה בנות נחשפו, נרשמו והצטרפו דרך כל אחת), קבוצות (פעילות, גודל, הגדולות, נסגרו), אתגרים ודיווחים (פופולריים, קטגוריות, אחוז הצלחה), בטיחות. נתונים מצטברים בלבד, בלי אימיילים.

## מגבלות המסלול החינמי ואיך עומדים בהן

| משאב | מגבלה (Free) | מילה |
|---|---|---|
| Workers בקשות | 100,000 / יום | ~30 בקשות למשתמשת ליום (מסך + פעולות). 100 משתמשות פעילות ≈ 3% מהמכסה. נכסים סטטיים לא נספרים כבקשות Worker כשהם מוגשים ישירות |
| Workers CPU | 10 ms / בקשה | אין hashing כבד (לכן לא Better Auth עם scrypt); OAuth הוא I/O; בניית מצב ~1–3 ms |
| D1 קריאות | 5,000,000 שורות / יום | `GET /state` קורא כמה עשרות עד מאות שורות; רענון אוטומטי כל 45 שניות רק כשהמסך גלוי |
| D1 כתיבות | 100,000 שורות / יום | דיווח = 3–5 שורות; מילה חדשה = ~16 שורות |
| D1 אחסון | 5 GB | שנה של 1,000 משתמשות פעילות ≈ עשרות MB |

- כשמגיעים למכסה, Cloudflare מחזירה שגיאה (לא חיוב). השרת ממפה אותה להודעה ברורה: ״הגענו למכסת השימוש היומית״.
- `usage_daily` סופרת קריאות מצב ליום; `GET /api/health` לבדיקת חיים. ניטור מפורט: Cloudflare Dashboard → Workers & Pages / D1 → Metrics.
- גיבוי: `npx wrangler d1 export mila-db-prod --remote --output backup.sql`. ייצוא אישי: הגדרות → ייצוא הנתונים שלי.
- סביבות נפרדות: Worker ו-D1 שונים ל-staging ולייצור; `ALLOW_TEST_LOGIN` כבוי בייצור.
